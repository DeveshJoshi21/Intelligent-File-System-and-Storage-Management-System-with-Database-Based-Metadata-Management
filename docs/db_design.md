# Database design

## Table: `files`
- `id`: integer primary key generated by SQLite.
- `absolute_path`: normalized absolute path; `UNIQUE NOT NULL`, used as the stable identity.
- `filename`: basename of the file.
- `extension`: lowercase suffix, or `[no extension]`.
- `size_bytes`: integer, nonnegative.
- `created_at`: UTC ISO 8601 timestamp if the platform exposes a birth/creation time; otherwise `NULL`.
- `modified_at`: UTC ISO 8601 timestamp from the filesystem modification time; `NULL` only if unavailable.
- `scanned_at`: UTC ISO 8601 time when the scanner took the metadata snapshot.
- `content_hash`: optional SHA-256 digest, computed on demand.
- `hash_checked_at`: optional UTC ISO 8601 time when the hash was computed.

## Constraints and indexes
- `id INTEGER PRIMARY KEY` gives each row a database identifier.
- `absolute_path UNIQUE NOT NULL` prevents duplicate records for the same normalized path.
- `size_bytes CHECK (size_bytes >= 0)` rejects invalid negative sizes.
- Indexes on filename, extension, size, modified time, and hash support common filters/reports.
- SQLite transactions are used through connection context managers. `upsert_many` commits the batch atomically or rolls it back if a database error occurs.

## Example queries
```sql
-- Count indexed files and total bytes
SELECT COUNT(*), COALESCE(SUM(size_bytes), 0) FROM files;

-- Storage by extension
SELECT extension, COUNT(*), SUM(size_bytes)
FROM files GROUP BY extension ORDER BY SUM(size_bytes) DESC;

-- Files larger than 1 MiB
SELECT filename, size_bytes FROM files WHERE size_bytes >= ? ORDER BY size_bytes DESC;

-- Find same-size groups as inexpensive duplicate candidates
SELECT size_bytes, COUNT(*) FROM files
GROUP BY size_bytes HAVING COUNT(*) > 1;

-- Parameterized filename search (the application binds the value)
SELECT filename, absolute_path FROM files WHERE filename LIKE ? COLLATE NOCASE;
```

## Dates and timestamps
Timestamps are stored as UTC ISO 8601 strings with an explicit `+00:00` offset. Date filters accept `YYYY-MM-DD`. Creation/birth timestamps are platform-dependent; Python's portable `st_ctime` has different meanings across platforms, so the app intentionally uses `st_birthtime` only when available and otherwise stores `NULL`. Modification time comes from `st_mtime`.

## Duplicate detection
Equal size is only a candidate signal, not proof of identical content. On request, the program computes SHA-256 for files in same-size groups. Matching SHA-256 values are strong evidence that the file contents match; the program does not delete anything. Hashing can take time and reads candidate file contents.
